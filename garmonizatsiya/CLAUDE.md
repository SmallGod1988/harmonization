# Гармонизация — игровой слой над аудитом времени

Веб-приложение в стиле игрового HUD: превращает лог времени владельца в нужды, настроение,
уровни навыков и недельные желания/страхи. Полное ТЗ — `docs/TZ_igrovoy_sloy.docx`.

Интерфейс и тексты — на русском. Отвечать владельцу тоже по-русски: спокойно, без «воды»,
списками, при неопределённости — один уточняющий вопрос.

## Запуск и обновление данных

```bash
python3 scripts/export_log.py путь/к/timelog_clean.xlsx   # Excel → data/data.json
python3 scripts/build.py                                  # src/app.html + data.json → dist/index.html
python3 -m http.server -d dist 8000                       # или просто открыть dist/index.html
```

Обратно в Excel: «Журнал» → «Выгрузить CSV», затем

```bash
python3 scripts/merge_log.py путь/к/timelog_clean.xlsx garmonizatsiya_ГГГГ-ММ-ДД.csv  # → timelog_clean_merged.xlsx
```

Исходный xlsx не перезаписывается — результат в `*_merged.xlsx`, заменить исходный вручную.

Нужен `openpyxl` (`pip install openpyxl`). Сборщиков и npm нет — это намеренно.

## Структура

- `src/app.html` — всё приложение одним файлом: разметка, стили, скрипт. Метка `__DATA__`
  заменяется содержимым `data/data.json` при сборке. **Редактировать здесь, не в `dist/`.**
- `scripts/export_log.py` — выгрузка из листа «ЛогВремени» (B акт, D сфера, G начало, H конец,
  J тип «основной»/«фон»).
- `scripts/build.py` — подстановка данных и обёртка в `<!doctype html>`.
- `scripts/merge_log.py` — слияние CSV-выгрузки приложения с «ЛогВремени». Ключ записи —
  начало до минуты + акт: есть с концом — пропуск, есть без конца — дописывается конец, нет —
  новая строка (B, D, G, H, J; формулы прочих столбцов переносятся из последней строки).
  Повторный прогон той же выгрузки ничего не меняет.
- `data/`, `dist/` — генерируются, в git не попадают (см. ниже).
- `docs/` — ТЗ.

## Личные данные — не коммитить

`data/data.json` и `dist/index.html` содержат реальный лог владельца за 35 дней (действия,
сферы, время). Оба в `.gitignore`. Не добавлять их в репозиторий, не вставлять реальные
записи в код, тесты и примеры. Для демо — делать отдельный синтетический набор.

## Формат data/data.json

- `entries`: `[unix_ts, часы, индекс_сферы, индекс_акта]` — закрытые записи за 35 дней,
  только тип «основной», интервалы 0–14 ч.
- `sphereNames`, `actNames` — справочники для индексов.
- `open`: `{t, act, sphere}` — последнее открытое действие (без конца).
- `totalSphere`, `totalAct` — накопленные часы за всё время (для навыков).
- `rate28Sphere`, `rate28Act` — часы за 28 дней (темп навыков).
- `actSphere` — самая частая сфера для акта (автоподстановка в форме).

## Модель (константы в начале скрипта `src/app.html`)

- **Время — московское, UTC+3 без перехода на летнее.** Все расчёты дней/недель идут через
  `OFF = 3*3600` и `getUTC*`, а не через локальное время браузера. Не менять на `getHours()` —
  у пользователя в другом поясе всё съедет.
- **Журнал — цепочка начал.** Каждая запись открывает действие и закрывает предыдущее;
  длительность = начало следующей − начало текущей (до 14 ч). Последнее действие «идёт» и
  засчитывается до точки отсчёта. Так же владелец ведёт лог в чате. См. `buildTimeline()`.
- **Нужды** (`NEEDS`): часы сферы в скользящем окне по времени начала ÷ норма, не выше 100%.
- **Настроение** (`moodAt()`): взвешенное среднее нужд × 100 − min(20, 2 × часы Хаоса за 7 дней).
- **Навыки** (`SKILLS`): порог уровня N = 50 × 1,8^(N−1), 10 уровней. Тип `act` — точный акт,
  `sphere` — вся сфера.
- **Неделя**: пн–вс. Страхи `min` сравниваются с нормой × доля прошедшей недели, иначе
  срабатывают каждый понедельник.
- **Точка отсчёта**: «пауза» — момент последней записи, «пуск» — сейчас. Если последней записи
  больше 12 ч, по умолчанию пауза, чтобы шкалы не обнулялись.
- График настроения — значение на 21:00 каждого дня (в 23:00 окно сна 24 ч теряет прошлую ночь).

Эти цифры совпадают с Excel-версией игры (листы «Персонаж», «Навыки», «Неделя» в
`timelog_clean.xlsx`), кроме одного: приложение засчитывает идущее действие, Excel — нет.

## Хранилище (`Store`)

Адаптер с тремя режимами, выбирается при старте:
1. `db` — сервер артефакта claude.ai (`window.claude.use('db')`), документы `days/ГГГГ-ММ-ДД`
   `{items:[{id,t,act,sphere}]}` и `state/wants` `{items}`. По дням — чтобы не упереться в
   лимит 5000 документов.
2. `local` — `localStorage`, ключ `garmonizatsiya.v2`. Так работает вне claude.ai.
3. `memory` — если хранилища нет.

Вне claude.ai `window.claude` нет — это нормально, адаптер уходит в `local`.

## Палитра

Тёмная тема одна и намеренно. Восемь цветов групп сфер в `GROUPS` проверены на различимость
(в том числе при нарушениях цветового зрения) на фоне `#0C2233`. Порядок и значения не менять
без перепроверки; девятая группа — только нейтральный цвет, не новый оттенок.

## Известные ограничения и следующие шаги

- **Обратная дорога в Excel — вручную**: «Выгрузить CSV» + `merge_log.py`. CSV: `;`, UTF-8 с BOM,
  даты `ДД.ММ.ГГГГ ЧЧ:ММ` (МСК), столбцы Акт;Сфера;Начало;Конец;Часы;Тип. Первая строка —
  открытое действие из Excel с концом = первая запись приложения; последняя — без конца.
  На claude.ai кнопка идёт через capability `downloads` (объявлять `{downloads: true}` при
  публикации), вне claude.ai — обычное скачивание. openpyxl при сохранении теряет диаграммы и
  кэш значений формул — поэтому пишем в отдельный файл.
- М7 «Карьерная лестница» из ТЗ не начат.
- Окна нужд по времени начала: интервал, начавшийся до границы окна, выпадает целиком.
- Нет редактирования записей — только отмена последней.
- Нужды, навыки, пороги страхов захардкожены в `src/app.html`; вынести в настройки — по запросу.
